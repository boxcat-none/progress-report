d:\廠商 · Ionic 8 + Angular 19 · MoveNet

長者體適能檢測 App：資料夾結構與執行流程

這是一個在瀏覽器或手機上跑的 Ionic 網頁 App。它用相機拍受測者，在裝置上用 MoveNet 偵測骨架，自動計次並評分四種測驗：椅子坐立、原地抬膝、單腳站立、椅子繞物。結果會送到後端 /fitness-api，LLM 建議則來自 /llm/encourage。

core 基礎設施 pages 一般頁面 exercises 測驗頁 shared 共用模組 靜態資源 / 設定

03SitStandPage 的內部分工

sit-stand.page.ts 本身幾乎不做計算，只負責決定現在該做什麼、該叫誰做。它用到的東西依「怎麼拿到手」分成三種：

new 出來的物件

頁面自己 new，每頁一份，有自己的狀態。例如相機、偵測器、追蹤器、計次器。

Angular 注入的服務

寫在 constructor(...) 參數裡，由 Angular 自動提供，全站共用一份。

純函式

直接 import 來呼叫，沒有狀態：給輸入、拿結果。例如 pose-utils、sit-stand-report。

測驗頁是一個狀態機。phase 記錄目前在哪個階段。每個階段有一個 enterXxx() 負責進入，一個 updateXxx() 負責每一幀的處理。不管在哪個已鎖定的階段，受測者離開畫面太久都會退回選人。

calib_sit坐著不動，倒數 5、4、3、2、1，畫預覽線倒數到 0 → 分界線 = 臀部最低點往上 2% 畫面高度

抬膝和單腳站立的階段較少（select_person → positioning → calib_stand → testing → done），校正改為站姿。椅子繞物有自己的流程（idle → seek_near → seek_far → sit_calib → pre_countdown → exercise → finished）。

07可以改進的地方

依影響程度排序，前兩項建議優先確認。

高

正式環境會略過登入檢查

environment.prod.ts 的 loginState 是 true，註解寫「正式環境時這個欄位不影響」，但真實的 AuthService.getUser() 和 isLogined() 一看到 loginState === true 就直接回傳假的 Mock User，不會去問後端。結果是所有人都被當成已登入，/chair-round 的 AuthGuard 也形同虛設。如果這不是刻意的暫時設定，改成 null 即可。

core/services/auth.service.ts:24、:83 · environments/environment.prod.ts:8

高

送出失敗的成績永遠不會補送

坐立、抬膝、單腳站立在上傳失敗時，會把成績存到 localStorage（sitstand_pending_summary、step_in_place_pending、single_leg_pending_summary），但整個專案沒有任何地方讀回來重送。而且每次只存一筆，下一次失敗就會蓋掉前一筆。建議在 App 啟動或登入後檢查並補送，並改成存陣列。

sit-stand.page.ts:664 · step.page.ts:635 · single-leg.page.ts:623

中

年齡固定是 30 歲

SitStandPage.readModeAndProfile() 把年齡寫死為 30，再送給 LLM 產生建議。實際受測者都是 65 歲以上，建議內容可能不貼切。ProfileService 已經有生日，可以直接算出年齡。

sit-stand.page.ts:201

中

年齡檢查只用年份相減

模式頁用「今年 − 出生年」判斷是否滿 65 歲，還沒過生日的人會多算一歲，64 歲也可能通過。日期下拉選單也固定 1–31 日，可以選到 2 月 31 日。

pages/mode/mode.page.ts · getAgeBandFromBirthday()

中

測驗頁沒有路由守衛，開發時也直連真實後端

登入和年齡只在 /mode 檢查，直接打開 /sit-stand 等網址可以跳過。另外 environment.ts 的 production 是 true，npm start 也會注入真實的 Data 服務；本機又沒有 /fitness-api 的 proxy，上傳必定失敗。

app/app.routes.ts · environments/environment.ts:4 · proxy.conf.json

中

示範影片太大

介紹頁的 3 支影片合計約 147 MB，手機用行動網路開啟會很久。轉成 720p H.264 通常可以降到每支幾 MB。

assets/椅子坐站運動.mp4 · 踏步.mp4 · 單腳.mp4

低

同一份 JSON 重複下載

fitness_standards.json 會被 ProfileService、FitnessStandardsService 和每個測驗頁各自下載；coach_template.json 也同時被 CoachScoreService 和測驗頁下載。可以集中到一個有快取的服務裡。

低

三個測驗頁有大量重複程式碼

讀取模式與受測者資料、載入 JSON、結束時上傳和存檔，這幾段在三個測驗頁幾乎一樣。抬膝和單腳站立已經改用 exercises/shared/report/exercise-profile.ts，坐立頁還是自己寫一份，可以統一。

低

頁面裡還有寫死的語音文字

AGENTS.md 規定參數放在 *.config.ts，但 sit-stand.page.ts 還有幾句語音直接寫在程式裡，例如「距離良好，請坐下保持不動…」、「開始運動。」、「受測者離開畫面，請重新點選。」。可以搬到 SIT_STAND_CONFIG.voice。

sit-stand.page.ts:349、444、451、526、566

低

核心演算法沒有測試

全專案 11 個 spec，exercises/ 底下只有椅子繞物頁一個。RepCounter、SitCalibrator、pose-utils 都是不依賴 Angular 的純邏輯，最容易寫測試，也最值得保護。

08資料庫選擇

PostgreSQL 是開源的關聯式資料庫，資料存成一張張表格，用 SQL 查詢。這一章是規劃，不是現有程式碼：目前成績只 POST 到 /fitness-api，失敗就存在 localStorage。改用 PostgreSQL 之後，成績可以長期保存，也能查歷史、做進步趨勢。

為什麼適合這個 App

資料本來就有關聯

一個使用者有多次測驗，一次測驗有多下評分，剛好對應 users → test_sessions → rep_scores 三張表，用外鍵串起來。

JSONB 欄位

每一下的評分細節（角度、時間、教練分數）格式可能會變，可以整包存成 JSONB，不必每次改欄位，之後也能查詢裡面的值。

交易（transaction）可靠

一次測驗的摘要和每一下的分數一起寫入，中途失敗就全部取消，不會只存到一半。

免費、生態成熟

Node、Python、.NET、Java 都有成熟的連線套件和 ORM。

前端不能直接連資料庫

Ionic / Angular App 跑在使用者的瀏覽器裡，直接連資料庫會讓帳號密碼曝光。App 只呼叫 API，查詢資料庫和檢查登入都在後端做。
